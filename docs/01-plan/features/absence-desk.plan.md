## 핵심 요약

| 관점 | 내용 |
|---|---|
| **문제** | 부재 담당자 전화를 하루 10건 이상, 건당 5분씩 대신 받아요. 부재여도 전화가 그대로 연결되고, 고객·물건 확인이 전화와 연결돼 있지 않아요 |
| **해결 방법** | ① 고객이 연결 전에 부재 안내를 듣고 회신 예약을 남기게 해요. ② 대신 받을 때는 이름 + 끝 4자리로 고객과 물건을 바로 보여주고, 문의는 AI가 3줄로 요약해요 |
| **기능·사용 효과** | 대리응대 건수가 줄고, 대신 받은 건도 묻고 찾는 시간이 줄어요. 담당자는 복귀 후 목록에서 바로 회신해요 |
| **핵심 가치** | 헛걸음 통화 감소 + 빠른 고객·물건 확인 + 부재 사유·개인정보 보호 |

## 1. 개요

### 1.1 목적

부재 담당자 앞으로 오는 전화를 연결 전에 걸러서 대리응대 건수를 줄여요. 그래도 대신 받아야 하는 건은 한 화면에서 빠르게 끝내요.

### 1.2 배경

PRD 1~2번 참고. 핵심 불편은 두 가지예요.
- 부재여도 전화가 그대로 연결돼요.
- 고객이 말하는 소재지를 듣고 물건을 직접 찾아야 해요.

### 1.3 관련 문서

- 기획서: [PRD.md](../../../PRD.md)
- 다음 문서: [설계서](../../02-design/features/absence-desk.design.md)

## 2. 범위

### 2.1 만들 것 (PRD 6번)

- [ ] 고객용 화면(전화 흉내): 담당자 선택(이름 또는 담당 지역) → 부재 안내 → 회신 받기 / 지금 통화
- [ ] 대리응대자 화면: 이름 + 끝 4자리(+ 생년월일 6자리) → 고객·물건 표시 → 문의 입력 → AI 3줄 요약 → 저장
- [ ] 담당자 화면: 이름 선택 → 내 목록 → 처리 완료
- [ ] 지표 화면: PRD 3번 숫자 자동 집계
- [ ] 예시 화면 3개(동작 없음): 전화 수신 팝업, ARS 부재 안내 흐름, 메신저·k홉스 알림
- [ ] 가상 샘플 데이터 + 서버 메모리 저장(시연용)

### 2.2 만들지 않을 것 (PRD 6번)

- 실제 전화 시스템 연결(ARS, CTI/PBX, 자동 팝업)
- 실제 고객 정보·물건 대장 사용, 사내 전산 연결
- 주민등록번호를 다루는 모든 기능
- 복무 시스템·메신저·k홉스 실제 연동
- 음성 인식, 문자·알림톡 발송
- 사내 로그인(SSO), 권한 등급
- nice 기능 4가지

## 3. 요구사항

### 3.1 기능 요구사항

ID 옆 괄호는 PRD의 개발 단위 번호예요.

| ID | 요구사항 | 기능 | 우선순위 |
|---|---|---|---|
| FR-01 (1) | 공통 머리글과 "실습용 화면입니다. 실제 고객 정보를 입력하지 마세요" 띠를 모든 화면에 표시해요 | 기반 | 높음 |
| FR-02 (2) | 접근 코드가 맞아야 화면과 서버 API를 쓸 수 있어요 | 기반 | 높음 |
| FR-03 (3) | 가상 샘플 데이터: 담당자 4명, 부재 일정, 고객 20명(동명이인 포함), 물건 30건 | 기반 | 높음 |
| FR-04 (4) | 서버 메모리 저장소: 샘플로 시작하고, 회신 예약·문의를 저장·조회해요 | 기반 | 높음 |
| FR-05 (5) | 부재 판단: 하루 단위로 보고, 주말·공휴일을 사이에 둔 부재는 이어서 마지막 날짜를 찾아요. 복귀일 미정도 처리해요 | must 1 | 높음 |
| FR-06 (6) | 부재 안내 문구: AI 없이 고정 문구에 이름·날짜를 끼워요. 2문장, 80자 이내이고 사유는 넣지 않아요 | must 1 | 높음 |
| FR-07 (7) | 고객용 화면: 담당자를 이름 또는 담당 지역으로 선택 → 안내 → "회신 받기 / 지금 통화". 부재가 아니면 바로 "연결" 단계로 가요 | must 1 | 높음 |
| FR-08 (8) | 회신 예약: 이름·끝 4자리·회신 번호는 필수, 문의 한 줄(100자)은 선택이에요. 같은 담당자·고객의 미처리 건이 있으면 "추가 연락 ○회"로 합쳐요 | must 1 | 높음 |
| FR-09 (9) | 고객 찾기: 이름 + 끝 4자리가 정확히 일치해야 해요. 2명 이상이면 생년월일 6자리로 좁히고, 0명이면 이름 + 생년월일로 다시 찾아요. 그래도 2명 이상이면 "담당자 확인 필요"로 둬요 | must 2 | 높음 |
| FR-10 (10) | 대리응대자 화면: 찾은 고객과 그 고객의 물건을 최대 5건 보여줘요. 못 찾으면 "고객 미확인"으로 진행해요 | must 2 | 높음 |
| FR-11 (11) | 문의 입력: 전화번호 전체·주민등록번호 형태가 있으면 막고 안내해요 | must 2 | 높음 |
| FR-12 (12) | AI 3줄 요약: 고객 요청 / 확인된 사항 / 담당자가 할 일. 이름·번호·생년월일은 보내지 않아요. 실패하면 직접 3줄을 써요 | must 2 | 높음 |
| FR-13 (13) | 대리응대 문의 저장: 시작(고객 찾기 시작)부터 저장까지의 처리 시간을 자동 기록해요 | must 2 | 높음 |
| FR-14 (14) | 담당자 화면: 이름 선택 → 미처리/처리 완료 목록(회신 예약 + 대리응대 메모) → 처리 완료 | 마무리 | 높음 |
| FR-15 (15) | 지표 화면: 대리응대 건수, 1건 처리 시간, 하루 합계, 물건 표시 비율, 전달 빈칸 건수 | 마무리 | 중간 |
| FR-16 (16) | 예시 화면 3개, "예시 화면" 표시, 버튼은 동작하지 않아요 | 마무리 | 중간 |
| FR-17 (17) | 흐름 A → B → C 전체 점검 후 Vercel 배포 | 마무리 | 높음 |

### 3.2 지표를 세는 방법 (PRD 3번과 연결)

| 지표 | 세는 방법 |
|---|---|
| 하루 대리응대 건수 | 고객용 화면에서 "지금 통화"를 고른 횟수 + 대리응대자 화면에서 저장한 건수 (시연 데이터 기준) |
| 1건 처리 시간 | FR-13의 시작~저장 시간 평균 |
| 하루 대리응대 시간 | 오늘 처리 시간의 합계 |
| 물건 표시 비율 | 고객 찾기 시도 중 최종 1명으로 찾아진 비율. 생년월일 추가 확인 포함 (PRD Q5) |
| 전달 빈칸 | 저장된 건 중 이름·끝 4자리·회신 번호·물건(또는 "미확인")·요약 중 빈칸이 있는 건수 |

> 지금 값(10건, 5분)은 실제 전화 기준이고, 앱의 숫자는 시연 데이터 기준이에요.
